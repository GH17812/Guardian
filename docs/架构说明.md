# Guardian 架构说明

## 1. 分层与依赖方向

```
Guardian.App (WPF)
      │  IPC (Named Pipe)
      ▼
Guardian.Service ── Guardian.Infrastructure (Pipe Server / 身份校验)
      │                 Guardian.Contracts (协议/DTO)
      ▼
Guardian.Core (保护引擎，纯托管、无系统依赖)
      │  Ports (接口)
      ▼
Guardian.Windows (Win32 适配层)   Guardian.Storage (SQLite)
```

依赖规则：
- `Guardian.Core` 不引用 WPF 与具体 Windows API，仅依赖 `Guardian.Contracts`；
- 所有 P/Invoke 收敛在 `Guardian.Windows.Interop` 与 `Guardian.Infrastructure.Interop`；
- UI 不直接执行任何高权限系统操作。

## 2. 保护引擎（Guardian.Core）

- `ProtectionEngine`：保护状态的唯一权威。单锁串行化命令；定时器驱动会话超时、心跳判定、电源检测。
- `PolicyAggregator`：手动保护 + 全部活动会话 → 目标策略（模式取最高、任一来源有效则保持系统运行）。
- `SessionManager`：会话生命周期与超时。
- `RecoveryCoordinator`：恢复三步（解除输入隔离 → 恢复显示 → 释放电源），单步失败不影响后续，结果如实记录。
- `CapabilityState`：能力报告（设备探测来自服务端，显示隐私验证随用户确认更新）。
- fail-open 规则：适配器调用异常 → 立即执行恢复并置 `Failed`；恢复本身也失败 → 保持 `Failed`，UI 显示"异常"。

## 3. 系统适配层（Guardian.Windows）

| 适配器 | 机制 | 释放 |
|---|---|---|
| DisplayPrivacyController | `BroadcastSystemMessage(BSM_APPLICATIONS, WM_SYSCOMMAND, SC_MONITORPOWER, OFF)` + 5s 重申 | 广播 `MONITOR_ON` |
| PowerRequestController | 专用线程持有 `SetThreadExecutionState(ES_CONTINUOUS\|ES_SYSTEM_REQUIRED[\|ES_DISPLAY_REQUIRED])`，60s 重申请 | 线程退出即系统自动释放 |
| InputIsolationController | `WH_KEYBOARD_LL`/`WH_MOUSE_LL` 钩子线程：无 INJECTED 标记 → 拦截；紧急组合键（Ctrl+Alt+Shift+主键）→ 回调引擎 | 摘钩 + 线程退出 |
| InputCapabilityDetector | Raw Input 枚举（键盘/鼠标/触摸屏/触控板/手写笔/手柄） | - |
| SystemStateReader | `GetSystemPowerStatus` / `GetSystemMetrics(SM_REMOTESESSION, SM_CMONITORS)` / `GetTickCount64` | - |

服务运行在 Session 0：显示消息使用 `BroadcastSystemMessage` 跨会话；低层钩子全局生效（安全桌面除外）。

## 4. 通信与安全（Guardian.Infrastructure）

- 管道：`Guardian.Control.v1`，长度前缀 JSON 帧，协议版本握手。
- 管道 ACL：SYSTEM / Administrators 完全控制，Users 读写（仅本机用户可连接）。
- 带内授权：通过 `GetNamedPipeClientProcessId` + `QueryFullProcessImageName` 取得调用进程路径；敏感命令（启用/解除/恢复/会话/设置）要求调用方为受信任进程名（Guardian.App.exe / Guardian.Cli.exe）、安装目录内进程或提权调用方。
- 故障隔离：管道处理器异常不会影响引擎；引擎错误以错误码返回。

## 5. 持久化（Guardian.Storage）

SQLite 单库（WAL）：`settings` / `sessions` / `operation_logs` / `recovery_records` / `capability_reports`。
- 服务以 SYSTEM 运行 → `C:\ProgramData\Guardian\guardian.db`；控制台开发模式 → `%LOCALAPPDATA%\Guardian\guardian.db`。
- 隐私承诺：不保存屏幕内容、键鼠输入内容、AI 对话内容。

## 6. 关键时序

**开启保护**：校验（模式可用性、RDP 隔离策略、显示隐私验证确认）→ 电源（防休眠）→ 输入（隔离时）→ 显示（关闭）→ 置 `Active` → 日志/快照。
**解除**：按剩余会话重算策略；无来源时按"显示恢复 → 输入解除 → 电源释放"反向执行。
**紧急恢复**：置 `Recovering` → RecoveryCoordinator 三步 → 结束全部会话 → 置 `Inactive/Failed` → 恢复记录。
**服务启动**：能力检测 → 载入持久化会话 → `StartupRestore`（fail-open）→ 按 ResumePolicy 决定是否 `ResumeAfterRestart` → 启动管道。
**客户端丢失**：`Ping` 兼作心跳；超阈值且策略为 Recover → 自动恢复。
**服务崩溃**：执行状态请求随进程失效；SCM 按 `sc failure` 配置重启服务，启动路径执行恢复。
